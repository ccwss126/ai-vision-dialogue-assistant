# AI Vision Dialogue Assistant 设计文档

## 1. 项目背景

开发一款 AI 视觉对话助手，通过摄像头获取环境画面，通过麦克风获取用户问题，并结合多模态 AI 进行回答。

项目目标是让用户在浏览器中完成“看见画面、听到问题、生成回答、语音播报”的完整闭环。前端负责摄像头、麦克风、语音识别、截图和语音播报；后端负责接收当前画面与用户问题，并调用 Gemini Vision API 完成视觉理解与回答生成。

## 2. 用户故事（计划）

* 用户可以开启感知（摄像头+麦克风）
* 用户可以通过语音提问
* AI 可以分析当前画面
* AI 可以回答用户问题
* AI 可以语音播报回答
* 用户可以查看历史对话

## 3. 最终实现的用户故事

* 用户可以点击“开启感知”，同时授权摄像头和麦克风。
* 用户可以看到摄像头实时预览。
* 开启感知后，系统会自动启动中文语音识别。
* 语音识别结果会填入输入框，用户可以手动修改后再点击分析。
* 用户点击“分析当前画面”后，前端会截取当前视频帧并发送问题。
* Go 后端会接收 `imageBase64 + question`，调用 Gemini Vision API 生成回答。
* 如果没有配置 Gemini Key，或 Gemini 网络请求失败，后端会自动返回 Demo Mode 回复。
* AI 回复会展示在对话历史中。
* 用户可以开启或关闭语音播报。
* 开启语音播报时，AI 回复后会自动使用中文语音朗读。
* 用户可以点击“停止播报”中断当前朗读。

## 4. 系统架构

前端：
Vue3 + Vite

浏览器能力：

* getUserMedia
* Web Speech API
* SpeechSynthesis API

后端：
Go

AI：
Gemini Vision API

前端通过 `navigator.mediaDevices.getUserMedia({ video: true, audio: true })` 获取摄像头和麦克风权限。语音识别在浏览器端完成，避免上传原始音频。发送分析时，前端将当前视频帧压缩为 640px 宽度以内的 JPEG base64 图片，并和用户问题一起发送到 Go 后端。

Go 后端提供 `POST /api/analyze` 接口，读取环境变量 `GEMINI_API_KEY`，调用 Gemini Vision API。如果 Key 缺失或请求失败，后端返回 Demo Mode 响应，保证演示流程不中断。

## 5. 用户交互流程

开启感知
↓
用户语音提问
↓
语音转文字
↓
截取当前视频画面
↓
发送图片+问题
↓
Gemini分析
↓
返回答案
↓
语音播报

## 6. 成本控制策略

设计阶段考虑：

* 图片压缩
* 请求去重
* Demo Mode
* 调用次数统计
* 问题为空不发送

实际采用：

* 图片压缩到640px
* Gemini失败自动切换Demo Mode
* 请求期间禁止重复发送
* 问题为空不调用模型
* AI调用次数统计

此外，项目没有上传连续视频流，也没有上传原始麦克风音频。语音识别由浏览器 Web Speech API 完成，云端只处理用户点击分析时的一帧图片和一段文本问题。

## 7. 未完成内容

例如：

* 实时视频流理解
* 多轮记忆
* 长时上下文
* 视频连续分析

原因：
受比赛开发周期限制，优先保证核心链路完整。

## 8. 总结

本项目实现了 AI 视觉对话助手的核心闭环：浏览器统一开启摄像头和麦克风，自动识别用户语音，将当前画面和问题交给 Gemini Vision 分析，并展示及播报回答。

后续可以扩展为更实时的多模态助手，例如增加连续关键帧采样、多轮上下文记忆、回答打断、调用额度控制、用户会话管理和更细粒度的模型路由策略。
