# AI 视觉对话助手设计文档

## 方案概述

应用由 Vue3 + Vite 前端和 Go 后端组成。前端负责摄像头预览、麦克风权限、浏览器端语音识别、截图压缩和语音朗读；Go 后端负责接收 `imageBase64 + question`，调用 Gemini Vision API，并在无 Key 或网络失败时返回 Demo Mode。

当前实现不是连续视频流对话，而是“开启感知 + 回合制视觉问答”：用户点击“开启感知”后同时打开摄像头和麦克风权限；用户点击圆形麦克风按钮说话，确认识别文字后，前端截取当前视频帧并发送给 Go 后端。这样能让 AI 看到当前画面、听到用户说话，同时控制云端调用成本。

## 用户故事

### 计划实现

1. 作为用户，我希望一键开启摄像头和麦克风，让应用进入 AI 感知状态。
2. 作为用户，我希望看到摄像头实时预览，知道 AI 将基于什么画面回答。
3. 作为用户，我希望点击麦克风自然说话，而不是手动输入问题。
4. 作为用户，我希望语音识别文本先预览，避免识别错误直接发送。
5. 作为用户，我希望 AI 根据当前画面和我的语音问题给出回答。
6. 作为用户，我希望 AI 回答可以被朗读出来，形成更自然的语音交互。
7. 作为用户，我希望看到历史对话和当时发送的画面截图。
8. 作为开发者，我希望没有 Gemini Key 或网络异常时仍可演示完整流程。

### 最终实现

1. 已实现“开启感知”，调用 `navigator.mediaDevices.getUserMedia({ video: true, audio: true })`。
2. 已实现摄像头实时预览和“关闭感知”。
3. 已实现中文语音识别，使用浏览器 Web Speech API。
4. 已实现识别文本预览，用户点击勾号确认后才发送。
5. 已实现发送时截图，并压缩到 640px 宽度以内。
6. 已实现 Go 后端 `POST /api/analyze`，请求格式为 `{ imageBase64, question }`，响应格式为 `{ success, mode, answer }`。
7. 已实现 Gemini Vision 调用，结合图片和用户语音问题回答。
8. 已实现 AI 回复展示和 SpeechSynthesis 朗读。
9. 已实现对话历史，展示用户问题、AI 回复和发送时截图。
10. 已实现 Demo Mode fallback：无 `GEMINI_API_KEY` 或 Gemini 网络失败时返回模拟回复。
11. 已实现 CORS 和代理环境变量支持：`HTTP_PROXY`、`HTTPS_PROXY`。

## 视觉理解准确性

1. 发送时截取当前视频帧，避免用户看到的画面和 AI 分析的画面不一致。
2. 使用 JPEG 压缩并限制宽度到 640px，在成本和清晰度之间取平衡。
3. 后端提示词要求模型结合图片内容和用户问题，且在信息不足时说明不确定点。
4. 历史记录展示发送时截图，便于用户核对 AI 回答的视觉依据。

## 语音交互自然度与流畅性

1. 统一“开启感知”请求摄像头和麦克风权限，降低用户理解成本。
2. 语音识别输入整合在摄像头下方的对话输入区，不作为单独窗口。
3. 使用圆形麦克风按钮和声波动画反馈录音状态。
4. 识别后显示勾号/叉号，用户可确认或取消，避免误识别直接触发云端调用。
5. AI 回复返回后自动朗读，形成“说话 - 看画面 - 听回答”的闭环。

## 成本控制策略

### 想到的技巧

1. 不连续上传视频流，只在用户确认问题后截取单帧图片。
2. 不上传原始音频，使用浏览器 Web Speech API 在本地完成语音转文字。
3. 图片压缩到 640px，减少请求体和视觉 token 成本。
4. 问题为空不请求，发送中禁止重复请求。
5. 记录 AI 调用次数，便于后续接入额度提示或计费统计。
6. 使用轻量 Gemini 模型作为默认模型。
7. Gemini 失败进入 Demo Mode，避免失败重试造成额外成本。
8. 可进一步按问题类型判断是否需要视觉调用。

### 实际采用

1. 已采用单帧截图，不上传连续视频。
2. 已采用浏览器端语音识别，不上传麦克风原始音频。
3. 已采用 640px 图片压缩。
4. 已采用空问题拦截和 loading 状态防重复请求。
5. 已在页面记录 AI 调用次数。
6. 已采用 `gemini-2.5-flash` 默认模型。
7. 已实现 Demo Mode fallback。
8. 已支持代理环境变量，减少网络失败和重复调试成本。

## 后续可改进

1. 支持连续低频关键帧采样，让 AI 获得更强的视频上下文。
2. 增加本地 VAD 端点检测，减少误触发识别。
3. 增加回答打断和连续追问能力。
4. 加入调用额度、冷却时间和每日调用次数限制。
5. 对历史上下文做摘要，避免多轮对话成本持续增长。
